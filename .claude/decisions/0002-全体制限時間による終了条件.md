# 0002 全体の制限時間によるゲーム終了とコンボ
- 日付: 2026-10-26
- 状態: 確定
- 関係する SPEC: 3.3 ゲームの終了条件とスコア（タイムアタック）

## 背景
ゲームに終わりがなかった。ユーザーの方針は「成功し続けることでクリアにはならず、なんらかの条件で失敗するまではプレイし続けることができ、終了時のスコアを競う形」。

## 決定
- 1プレイ全体に制限時間を設ける（ユーザーが D案を選択）。
- 「鉱石を発見した際は専用の制限時間を設け、全体の時間は止め」る（ユーザー指示）。実装では、鉱石が出現してから採掘結果が出るまで全体の時間を止める。
- コンボボーナスを追加する。「ミスせずに連続で成功を一定数続けた場合、制限時間が数秒（要調整）伸びる」（ユーザー指示）。
- 最高記録はコースごとに分けてブラウザ（localStorage）に保存する（ユーザー指示）。
- 以下の初期値は Claude が仮に決めたもので、プレイしながら調整する（`src/data/gameRules.ts`）:
  全体 90秒 / コンボ 5 ごとに +5秒 / コンボボーナス (コンボ−1)×2点・上限 +20点 / 結果画面で Enter を受け付けるまで 1.2秒。
- 「成功」はモンスター撃破と鉱石採掘成功。コンボはミスタイプと鉱石の時間切れで 0 に戻る（減点はしない）。

## 検討して採らなかった案
- A. 鉱石を逃がすとハートが減り、0 で終了 → ユーザーが D案を選択したため不採用
- B. モンスターが目の前まで来るとダメージ → 通常フェーズの「時間制限なし」と矛盾し、速さ優先になるため Claude が非推奨とした
- C. 進むほど難しくなる（制限時間短縮・文字数増加） → 単独では終了条件にならない補助案。D案では採用せず
- E. ミス回数の上限 → 「ミスは減点しない」と矛盾し、間違いを怖がらせるため Claude が非推奨とした

## 見直す条件
数値（制限時間・コンボ条件・のびる秒数）は「要調整」とユーザーが明言。実際に遊んで長すぎる／短すぎる場合は `gameRules.ts` を調整し、ここに更新履歴を残す。

## 更新履歴
- 2026-10-26: ユーザーが実際に遊んだうえで調整を指示。全体の制限時間 90秒 → 60秒、コンボで伸びる時間 5秒 → 2秒（`src/data/gameRules.ts`）。
