# 経緯ログの記録

引数: $ARGUMENTS

`.claude/decisions/` に仕様変更の「なぜ」を残す。書式とルールは `.claude/CLAUDE.md` の「6. Decision Log Rule」に従う。

## 1. どちらの操作か判断する
- 引数が `NNNN 状態`（例: `0001 確定`、`0003 撤回`）の形 → **状態の更新**（手順 3）
- それ以外（決定の内容、または空） → **新規の記録**（手順 2）
  - 引数が空なら、直前までの会話で決まった方針を記録対象にする。対象が判断できなければ、何を記録するかユーザーに聞く。

## 2. 新規の記録
1. `.claude/decisions/INDEX.md` と `.claude/decisions/TEMPLATE.md` を読む。
2. 同じテーマの既存の記録がないか INDEX で確認する。あれば新規ではなく、その記録の更新か「置き換え(→NNNN)」にするべきかを検討する。
3. 番号は `.claude/decisions/` 内の `NNNN-*.md` の最大番号 + 1（4桁ゼロ埋め。なければ 0001）。
4. `NNNN-題名.md` を TEMPLATE に沿って作る。題名は短い日本語。
   - 中身は会話・コード・SPEC.md から分かる事実だけで書く。分からない項目は推測で埋めず「（未記入）」とし、報告時にユーザーに伝える。
   - ユーザーの発言（「イマイチなら削除」など）は、言い回しをなるべく残して「見直す条件」などに書く。
   - 状態は、ユーザーが試験的と言っていれば「試験導入」、そうでなければ「確定」。
   - 「関係する SPEC」は `.claude/SPEC.md` の章番号と章名。
5. `INDEX.md` の表の末尾に `| NNNN | 題名 | 状態 | YYYY-MM-DD |` を1行追加する。
6. この決定で仕様が変わるのに SPEC.md が未反映なら、SPEC.md の該当箇所と「変更履歴」（`→ D-NNNN` を添える）も更新する。

## 3. 状態の更新
1. 該当する `NNNN-*.md` を読み、`状態:` の行を新しい状態に書き換える。
2. 本文の末尾に `## 更新履歴` 節がなければ作り、`- YYYY-MM-DD: 試験導入 → 確定（理由）` の形で追記する。理由が会話から分からなければユーザーに聞く。過去の記述は消さない。
3. `INDEX.md` の該当行の状態も合わせて書き換える。
4. 撤回なら、「見直す条件」に書かれた戻す箇所を実際に戻すかどうかをユーザーに確認する（このコマンドではコードを変えない）。戻す場合は SPEC.md も更新する。

## 4. 報告
作成・更新したファイル、番号、状態を短く伝える。「（未記入）」の項目があれば挙げる。
